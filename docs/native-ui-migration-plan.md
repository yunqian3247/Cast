# 原生界面迁移与内存优化计划

日期：2026-10-02。状态：初步计划，内存收益及控件方案通过原型验证后细化。

## 目标与现状

采用现有 WinForms、原生控件和自绘通信终端，逐步将 HTML/CSS/JavaScript 界面迁到 C#，最终移除 WebView2 运行依赖。保留现有功能、数据兼容性和界面布局，以降低空载占用及持续接收时的分配开销。

当前 WebView2 承载串口工具栏、通信终端、预设、工作流、发送区、弹窗及交互动效。C# 已负责串口收发、编码、分帧、执行控制、配置、持续日志和更新；启动图标动画由 `StartupSplash` 原生绘制。

现有实测空载合计 Private Bytes 约 358～360 MiB，其中浏览器相关进程约 325～329 MiB、C# 宿主约 32 MiB。持续接收阶段合计约 490～504 MiB。原生原型先以同机空载 **≤100 MiB** 为目标，最终数值通过测量确认。原始数据和测量限制见[性能记录](performance-audit-2026-10-02.md)。

## 迁移范围

| 部分 | 处理方式 |
|---|---|
| `cast.Core`、`cast.Serial`、`AppService` | 复用现有编码、串口、分帧和工作流逻辑，通过方法调用及事件连接界面。 |
| `AppDocument`、配置备份与迁移、持续日志、诊断、更新 | 保留数据格式及行为，接入原生窗口的保存、关闭和更新流程。 |
| 工具栏、预设栏、工作流栏、发送区和弹窗 | 用 WinForms 控件重建；按现有设计统一颜色、间距、字体和交互。 |
| 通信终端 | 实现自绘虚拟日志控件，覆盖可变行高、换行、协议释义、搜索、复制及滚动锚点。 |
| JS 中的协议翻译、搜索、导出和界面状态逻辑 | 迁入 C#，复用已有 HEX、CRC、校验及文件写入实现。 |
| 启动动画、图标与字体 | 复用现有资源和动画，调整资源加载路径，验证字形覆盖与 DPI。 |

原生控件方案参考微软的[自绘支持](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/controls/controls-with-built-in-owner-drawing-support)及[虚拟模式](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/controls/virtual-mode-in-the-windows-forms-datagridview-control)。通信终端的多行、展开和精确滚动行为通过专用控件原型确认。

## 实施阶段

### 1. 最小原型与基准

- 增加独立的原生窗口开发入口，使用隔离的数据目录；保留现有界面用于对照。
- 实现串口选择、连接、文本/HEX 发送、基础日志和字节统计，直接调用现有服务。
- 原生入口仅创建原生窗口，记录实际进程清单、启动耗时、Private Bytes、Working Set、托管堆及句柄数。
- 统一 Release x64、机器、配置、字体和输入样本，对比普通运行与带探针的测量。

阶段产物：可运行原型、空载基准和技术路线评估。以空载目标及基本收发结果作为后续完整迁移的依据。

### 2. 通信终端与数据模型

- 由 C# 数据模型统一保留日志，显示层通过 ID 或索引引用记录，绘制可见范围及少量缓冲行。
- 初期复用 `AppLog`；根据测量评估原始字节存储、按需 HEX 和协议释义。文本解码保留跨读取事件的连续接收语义。
- 为文本、协议解析和行高设置有界缓存，复用高度索引及批次缓冲。
- 将后台接收事件放入有界更新队列，每 20～50 ms 批量更新界面，显示队列溢出与历史裁剪计数。
- 实现文本/HEX/双显、筛选、完整历史搜索与导出、释义展开、复制、自动跟随及历史位置保持。

阶段产物：功能完整的通信终端、1 万条短/长记录对比及 30 分钟连续输入曲线。

### 3. 完整界面与交互

- 重建预设编辑与导入导出、工作流编排及应答控制、发送区、设置、错误记录和更新弹窗。
- 保留发送互斥、暂停/单步/停止、输入历史、严格编码、CSV 保护和大库文件容量规则。
- 原生窗口直接构建配置快照；关闭前保存失败时保留窗口，正常关闭时取消发送并刷新持续日志。
- 对齐深浅主题、快捷键、焦点、中文输入法、提示、可访问性、最小窗口和 DPI 行为。

阶段产物：原生界面完整功能清单、服务层回归和原生交互/截图测试。

### 4. 验收与切换

- 在相同条件下对比两版的功能、布局、启动、内存和长时间收发，逐项记录差异。
- 原生版验收通过后切换默认入口，移除 WebView2 控件初始化、JSON 消息桥、相关包引用和打包依赖。
- 整理字体与图标资源、测试入口、构建脚本和使用说明，保留现有配置及更新通道兼容性。

阶段产物：原生运行包、对比报告和更新后的验证说明。

## 验收要点

| 范围 | 验证方式与目标 |
|---|---|
| 空载 | 相同机器及默认配置，启动稳定后测量；目标合计 Private Bytes ≤100 MiB，并核对进程清单。 |
| 日志负载 | 1 万条短帧及 64 字节长帧，核对保留条数、字节、顺序、搜索和导出；记录稳态与峰值。 |
| 长时间运行 | 连续输入 30 分钟，达到保留上限后检查增长趋势；重复清空后检查恢复量、句柄及缓存。 |
| 交互与布局 | 深浅主题，880×560、1120×700、1920×1080，100%/150%/200% DPI；核对换行、输入法、焦点和快捷键。 |
| 数据与生命周期 | 旧配置恢复、大库往返、备份恢复、保存失败、关闭取消、日志刷新及更新前保存。 |
| 实体设备 | 双向通信、长时间收发、热插拔、物理引脚及多显示器切换，使用实际环境记录结果。 |

测量同时报告 Private Bytes 与 Working Set，记录采样条件；普通运行基准、诊断探针及强制 GC 对照分别保存。长负载的具体内存阈值在原型测量后制定。

## 重点风险

- 自绘终端需要维护可变行高、滚动锚点和展开状态，优先用长记录、频繁追加和历史浏览覆盖这些边界。
- 界面逻辑迁移涉及配置保存、错误反馈、中文输入法及关闭时序，按功能逐项对照现有实现。
- 控制字体缓存、GDI 资源和列表控件数量；绘制资源统一复用并在窗口关闭时释放。

首个实施里程碑为最小原生窗口与通信终端原型，通过实测决定完整迁移的控件细节和内存预算。
